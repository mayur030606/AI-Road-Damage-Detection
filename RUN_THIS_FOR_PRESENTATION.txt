ERROR PLAYBOOK — use the CASE that matches the screen

CASE A — ping 10.54.12.49 works, ssh works, but:
           "No cameras available!"
           "ERROR: *** no cameras available ***"
           "Failed to create egl preview"  (ignore this line on Lite OS / SSH)

  The "egl/drm preview" lines are NORMAL over SSH (no desktop). Ignore them.
  The real failure is "no cameras available" — libcamera cannot see IMX219.

  On the Pi, paste these one at a time:

    sudo killall rpicam-hello rpicam-vid libcamera-hello libcamera-vid 2>/dev/null || true
    ls -l /dev/video* /dev/media* 2>/dev/null
    dmesg | grep -iE 'imx|unicam|ov5647|camera' | tail -n 30

    sudo raspi-config
      Interface Options → I5 I2C → Enable → Finish
      (there is NO Camera menu on Trixie — that is OK)

    sudo apt install -y i2c-tools
    ls /dev/i2c-*
    sudo i2cdetect -y 10
    sudo i2cdetect -y 0
    sudo i2cdetect -y 1

  If you see "10" in the grid (address 0x10), the sensor is electrically alive.
  If every bus is empty (only "--"), the Pi still does not see the module:
    power OFF, flip the ribbon 180° test is WRONG — do not flip randomly.
    Confirm BLUE backing on Pi points to USB/Ethernet, silver to HDMI.
    Try the OTHER CSI port on Pi 5 (CAM/DISP 0 vs 1).
    Try a different ribbon if you have one.

  Force the overlay ONLY if dmesg has NO imx219 lines at all.
  If dmesg already shows "failed to read chip id 219", skip nano and go to CASE A2.

    sudo nano /boot/firmware/config.txt

  Prefer ONLY this (comment out extra dtoverlay=imx219 if both exist):

    camera_auto_detect=1
    dtparam=i2c_arm=on
    # dtoverlay=imx219

  Save: Ctrl+O, Enter, Ctrl+X
  Then full POWER OFF (unplug), not only reboot. Wait 15s. Plug in.


CASE A2 — dmesg shows:
           imx219 10-0010: Error reading reg 0x0000: -121
           failed to read chip id 219
           probe with driver imx219 failed with error -121

  THIS IS NOT FIXABLE IN PYTHON. The kernel overlay is already loaded.
  The Pi cannot talk to the sensor over the ribbon I2C (EREMOTEIO).
  Software, venv, YOLO, dashboard, and config.txt cannot read chip id 219.

  Do this once, in this order:

  1. sudo shutdown -h now
     Wait until the green LED stops. UNPLUG USB-C. Wait 20 seconds.

  2. On the Pi board CAMERA connector:
       Pull the black/plastic latch UP (both sides).
       Slide the ribbon fully OUT, then fully IN.
       Silver contacts face the HDMI / board edge (Pi 4).
       Blue plastic faces USB/Ethernet.
       Push latch DOWN until flush. Tug test: cable must not slide.

  3. On the CAMERA MODULE board:
       Same: latch up, cable out, in, latch down.
       Silver contacts face the LENS / front of the module.

  4. Use the official 5V 3A USB-C PSU (weak phone chargers drop camera 3.3V).

  5. Plug power in. Wait 60 seconds. SSH. Then:

       dmesg | grep imx219
       rpicam-hello --list-cameras

  SUCCESS looks like:
       0 : imx219 ...
  FAIL still looks like:
       failed to read chip id 219 / error -121

  If it still fails: the ribbon or the camera PCB is damaged (it worked earlier,
  then timed out, then this). Swap the FFC cable or the Camera Module v2.
  There is no more software step.

  PRESENTATION WITHOUT CSI (works today):
    Laptop: python scripts/mock_backend.py --port 8000 --conf 0.50
    Browser: http://127.0.0.1:8000
    Leave [ Demo video ] selected.
    That is the same pothole model on pothole1.mp4.


CASE B — "Camera frontend has timed out" / Dequeue timer expired

  Sensor was listed, then stream died. Causes: loose latch, 1280x720 (not native),
  or another process holding the camera.

    sudo killall -9 rpicam-hello rpicam-vid libcamera-vid python 2>/dev/null || true
    rpicam-hello -t 3000 --width 1920 --height 1080 --nopreview

  Never use --width 1280 --height 720 on this IMX219.
  If timeout continues: power OFF, reseat both ends, power ON, CASE A.


CASE C — ssh: Connection reset / kex_exchange_identification

  Pi is booting or SSH restarted. Wait 60s after power-on. Then:

    ping 10.54.12.49
    ssh shivraj@10.54.12.49

  Do not spam ssh during boot. Do not run "sudo shutdown" from Windows.


CASE D — Input/output error on logout / random I/O errors
